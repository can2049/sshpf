# 保存导入：一行一条隧道 / Save imported rows

> **这份文档回答**：`ctrl+s` 归谁（手填表单 vs 导入面板）、一条勾选行变成什么 `TunnelConfig`、端口怎么顺延、名称怎么去重、保存后的状态。
> **不负责**：哪些行会被列出（见 [import-forwards.md](import-forwards.md)）、面板交互与筛选与「已存在」行的表现（见 [import-pane.md](import-pane.md)）、转发身份去重（见 [dedup.md](dedup.md)）、对端端口批量（见 [port-scan.md](port-scan.md)）。
> **相关代码路径**：`src/app/form_submit.rs`（提交路由 + 单条路径）、`src/app/import.rs`（批量构建与提交）、`src/model/import.rs`（`plan_local_port`）、`src/config.rs`（`validate_tunnel`/`unique_name`）。

`ctrl+s`（或 `f10`）在**面板赢得提交**时走批量路径，**整批先校验、全过才写**：

```text
for each ticked forward:            ← 已保存的行根本不会被勾上（见 import-pane.md）
    TunnelConfig ← config_from_forward
    跳过：已保存的隧道 / 本批次前面的行里有同一转发（见 dedup.md）
    校验字段（validate_tunnel）
    校验监听地址冲突：已保存的隧道 + 本批次里前面的行
    通过 → 收进 out
errors 非空 → 错误写进表单，一条都不创建
否则 → append、persist 一次、逐条启动
```

"全部校验完才写"防的是**部分写入**：创建 3 条、第 4 条报错，用户会得到一个自己没要求过的状态。

## 提交归属：默认提议 vs 明确指令

面板**自动展开、自动全勾**是刻意的产品默认（"默认全选"必须是零额外按键就能拿到的初始状态）。所以「面板在屏幕上」**不能**独自等于「面板就是用户的意思」——它同样是"选完主机、然后开始手填一条具体转发"的状态。

判据（`App::import_pane_wins_submit`）：`非编辑态 && 面板可见 && 表非空 && (一行都没勾 ? 表单不完整 : 用户动过面板 || 表单字段不完整)`。

| 状态 | `ctrl+s` 做什么 | 表单字段 |
|---|---|---|
| 面板未被动过，手填字段**完整** | 单条：只按手填字段创建一条 | 校验并采用 |
| 面板未被动过，手填字段**不完整** | 批量：每条勾选行一条隧道 | 忽略（只是草稿） |
| 面板**动过**（勾选 / 筛选 / 手动 `space`/`i` 展开），且还有勾选行 | 批量：每条勾选行一条隧道 | 忽略（只是草稿） |
| 面板**动过但一行都没勾**（全不选 / 反选清空 / 筛选后全不选），手填字段**完整** | 单条：只按手填字段创建一条 | 校验并采用 |
| 面板**动过但一行都没勾**，手填字段**不完整** | 报「没有勾选任何转发」，不创建 | 不适用 |
| 面板已收起 | 单条：按手填字段创建一条 | 校验并采用 |

「动过」记在 `ImportTable::touched`（判据细节见 [import-pane.md](import-pane.md#touched默认提议-vs-用户意图)）：移动光标、点行选中、自动展开本身**不算**；换主机时清零。

这条规则修的是一个**实测吞掉用户输入**的缺陷：面板自动展开且全勾，用户手填 3082 端口后 `ctrl+s`，实际只创建了 `~/.ssh/config` 里的 2 条，3082 静默消失（旧判据是"面板可见即归属"）。修法不是取消自动展开，而是给「默认提议」与「明确指令」分优先级。手填胜出时状态栏说明「已创建手填的 1 条转发；导入面板的 N 条未创建」——面板带着勾选消失而无一行被创建，沉默会被读成"批量也跑了"。

第二条分支修的是同一族缺陷的另一半：**勾选被清空不等于"面板在发号施令"**。用户想要 `cloud_pc:3081`，而面板里是该主机既有的 18789/44897 两条——正确的动作就是把这 2 行取消勾选，再手填 3081。旧判据只看 `touched`，于是 `ctrl+s` 走批量路径、得到「没有勾选任何转发」，手填的 3081 连同表单一起卡在那里。**没有内容的指令不是指令**：勾选行数为 0 时面板只剩"报告没勾选"这一件事可做，只有在手填表单也不成形状时它才是有用的回答。

这条分支还覆盖一种**不需要用户动手就成立**的空面板：该主机在 `~/.ssh/config` 里的转发**全部已经建过**时，每一行都被标成「已存在」而不可勾选（[import-pane.md](import-pane.md#已存在的行--rows-that-already-exist)）。此时 `checked_count()` 恒为 0，用户按 `space`/`i` 手动展开面板（会置 `touched`）只为看看那几行为什么是灰的——`ctrl+s` 必须照旧保存他手填的那一条，而不是报「没有勾选任何转发」。判据用的是 `any_checked()`，它按 `creatable()` 计数，所以「存在但不可创建」与「用户取消勾选」被同一个规则正确覆盖。

原则一句话：**校验必须对着用户真正在用的那份界面**；反过来说，**没有可执行内容的那份界面不能赢**。

## `TunnelConfig` 字段怎么由指令填

| 指令 | `local_addr` / `local_port` | `remote_host` / `remote_port` |
|---|---|---|
| `-L` | 指令的**监听**端 | 指令的**目标**端 |
| `-R` | 指令的**目标**端 | 指令的**监听**端 |
| `-D` | 指令的**监听**端 | 空 / 0（SOCKS5 没有远端） |

`-R` 两端**对调**：`RemoteForward 7000 localhost:22` 里 `7000` 是服务端监听、`localhost:22` 是本地目标；而 `TunnelConfig` 的 `local_*` 永远是"本机这一侧"。填反了会静默转发错误的端口。监听地址为空时填 `defaults.bind`（默认 `127.0.0.1`）。

## 本地端口顺延 / Local port shifting

`-L`/`-D` 需要在本机 bind，所以先过 `plan_local_port`（与表单的建议逻辑**共用同一份规则**）：

| 情况 | 结果 |
|---|---|
| 端口 ≥1024 且可用 | 原样使用 |
| 端口 <1024（需 root） | 惯用别名 `remote + 2200`（`22 → 2222`），**不从特权区间向上扫** |
| 以上都不行 | 从 `max(port, 1024)` 向上扫，最多 200 个候选 |
| 200 个都不行 | **保留原端口**，让校验报出真正的问题，而不是静默改成 0 |

`-R` 不在本机监听，端口原样保留。特权端口不能在自己所在区间向上扫的原因：`port_available` 会把所有 <1024 的端口报成不可用（绑定需要 root），从那里起步会烧完整个扫描预算仍然找不到端口。

`taken` 列表在批次内**逐条增长**，所以同批次两行要同一端口时第二行被顺延；已保存但**未运行**的隧道也计入——它现在没在监听，但一旦启动就会冲突。

**顺延值会被持久化**，这一点是[转发去重](dedup.md)为什么不比本地端口的原因：`config.toml` 里存的是顺延后的数字，原始请求事后不可恢复。

## 名称 / Name

建议名 `<host>-<L|R|D>-<监听端口>`（如 `cloud_pc-L-8090`），两级去重：`unique_name` 对已保存隧道去重（→ `-2`），`unique_within` 对本批次内去重。

**名字描述配置里写了什么，不是运行时落在哪**：`8090` 被占而顺延成 `8091` 时，名字仍是 `cloud_pc-L-8090`。

## 保存后的状态

每条隧道 `enabled = true`，`persist` **一次**（不是 N 次），然后逐条启动；`note` 记 `来自 ~/.ssh/config 第 N 行` 便于回溯；表单关闭，光标落到**第一条**新建隧道上。

部分行因重复被跳过时，状态栏追加「跳过 N 条重复转发」；**全部**被跳过时创建 0 条、状态栏「N 条转发已存在，未重复创建」并且表单正常关闭——"你要求的事已经成立"不是错误。

## 已知边界 / Known limits

| 边界 | 行为 |
|---|---|
| 部分失败的批次 | 一条都不写（全有或全无），错误全部写进表单 |
| 编辑已有条目 | 永远单条 + 二次确认，不走批量（把一次编辑变成批量新建是数据丢失级问题） |
| 名称里的端口 | 是**请求**的端口，不是顺延后的 |
| 重复行 | 跳过而非报错；每条跳过记 `event=action.duplicate_skipped` |
| 行对应的转发已保存 | 该行**在列表里就不勾选**（`[✓]`），所以批量路径通常连"跳过"都不用记；能走到跳过说明是同批次内重复 |
